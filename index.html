読み方

接続 (rtt-open) と クエリ (rtt-read) は別のものを表している

  • 接続 は WebSocket が開くまで。DNS、TCP、TLS ハンドシェイクを含むので、ほぼ経路と距離の話になります。
  • クエリ は REQ を送ってから最初の EVENT か EOSE が返るまで。同じ場所から測るかぎり経路条件は共通なので、差はリレー自身のクエリ性能として読めます。
  • この2つは相関しません。接続が速くてクエリが遅いリレー、その逆も普通にあります。

1回目は遅い

  • DNS 解決と TLS ハンドシェイクが乗るため、初回は実力より遅く出ます。既定では3回測って中央値を採り、参考として最小値も併記しています。

測れないもの

  • ws:// (平文) は https ページからは mixed content として遮断されるため対象外です。.onion も同様に到達できません。
  • NIP-42 の認証必須リレーや有料リレーは REQ が拒否されるので、auth / closed として「遅い」とは区別して表示します。
  • 「実装」欄は NIP-11 の software / version です。CORS で取得できないリレーでは空欄になります。

測る相手の選び方

  • NIP-66 の監視レポートから候補を集めると 500 件以上になるので、既定では 報告している監視ノードが多い順に上位 60 件だけ測ります。多くの監視ノードが見ているリレーほど広く使われている、という近似です。上限は変更できます。
  • 手入力、?relay=、自前リレー、自分の kind 10002 から来たものは上限とは無関係に必ず測ります。

この値はあなたの視点のものでしかない

  • 同じリレーでも、測る場所が変わればまったく違う数字になります。ここでの結果は「あなたの回線から見たリレーの速さ」であって、リレーの絶対的な性能ではありません。
